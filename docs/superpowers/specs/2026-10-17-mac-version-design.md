# Mac-версия WaterCa7s PC Cleaner

Дата: 2026-10-17. Статус: одобрено пользователем по частям; перенесено в отдельный репозиторий по его решению.

## Цель

Отдельная программа для macOS в отдельном репозитории `WaterCa7/WaterCa7-s-pc-cleaner-mac` (публичный, MIT). Вид как у
Windows-версии (`WaterCa7/WaterCa7-s-pc-cleaner`): тёмная тема, акцент `#34D399`, иконка «кошачья капля». Весь интерфейс
на русском, те же правила безопасности и та же схема автообновления. В первой версии — все пять разделов: «Главная»,
«Очистка и диски», «Процессы и автозагрузка», «Программы», «Безопасность и сеть» (плюс небольшие «Настройки»). Цель —
Mac с Apple Silicon (M1–M4), macOS 14 Sonoma и новее.

Готово, когда: программа со всеми разделами работает на macOS, проверена на машине macOS в GitHub Actions и
пользователем на его Mac; CI собирает `.app`; все тесты зелёные; релиз публикуется только после согласия пользователя.

Не входит в первую версию: сборка для Intel (`osx-x64`), подпись Developer ID и нотаризация, очистка системных папок
(`/Library/Caches`, `/private/var/log`), проверка расширений браузеров, удаление снимков Time Machine, значок в строке
меню и фоновое наблюдение, английский интерфейс, изменения в репозитории Windows-версии.

## Решения пользователя

- C# + Avalonia **12.1.4**, **net10.0** (поддержка .NET 8 кончается 10.11.2026; .NET 10 — LTS до ноября 2028, ему нужна
  macOS 14+).
- **Отдельный публичный репозиторий** `WaterCa7/WaterCa7-s-pc-cleaner-mac` (MIT): свои версии (первая — **1.0.0**), свои
  релизы, свой `update.json`, свой CI. Репозиторий Windows-версии не меняется. Публичный — чтобы автообновление
  скачивало релизы без входа в GitHub.
- .NET 10 SDK на ПК разработки стоит (winget, `Microsoft.DotNet.SDK.10`); Windows-версия на нём проверена.
- Подпись — **самоподписанный сертификат** подписи кода (секреты `MAC_SIGNING_P12`, `MAC_SIGNING_PASSWORD`, резервная
  копия у владельца). Так macOS сохраняет «Полный доступ к диску» и другие разрешения после автообновления (у ad-hoc
  подписи нет постоянного требования подписи, и разрешения сбрасываются с каждой новой сборкой). Пока секретов нет —
  подпись ad-hoc (`codesign -s -`).
- Кэши и журналы программ **удаляются** (программы создадут их заново, место освобождается сразу); всё, что нельзя
  восстановить, — **в Корзину**.
- Общий с Windows код **копируется** в `src/PcCleaner.Mac/Shared/`; откуда и с какого коммита взят каждый файл, записано
  в `Shared/SOURCE.md`. Исправления общего кода переносятся вручную в обе стороны.

### Сервисы Core

Каждый сервис появляется в том этапе, который первым его использует.

- `CommandRunner` (`ICommandRunner`, этап 1) — запуск утилит только по полному пути (`/bin/launchctl`,
  `/usr/bin/codesign`, …), аргументы списком, без shell, таймаут, `LC_ALL=en_US.UTF-8`; результат: код выхода, stdout,
  stderr, признак таймаута. В тестах — `FakeCommandRunner` с сохранённым выводом из `Fixtures`.
- `Plist` (этап 1) — разбор XML plist (чистый код, DTD не обрабатывается); двоичный plist сначала переводится
  `plutil -convert xml1 -o - <файл>`.
- `AppPaths` (этап 1) — домашняя папка (в тестах — временная), данные `~/Library/Application Support/WaterCa7sPcCleaner`
  (`settings.json`, `Backups/`, `Updates/`), журналы `~/Library/Logs/WaterCa7sPcCleaner`.
- `Log`, `ErrorText`, `AppSettings`, `Dialogs` (`ConfirmAsync/AskAsync/InfoAsync/ErrorAsync`; в тестах и режиме
  скриншотов — всегда «Нет»), `PageViewModel`, `RelayCommand`, `AsyncRelayCommand`, `Ui.Post/Invoke` (этап 1) — Mac-версии
  с тем же API, что в Windows (`docs/ARCHITECTURE.md` Windows-репозитория), кроме того, что диалоги асинхронные.
- `MacShell` (этап 1) — `open <адрес>` и `open -R <путь>` («Показать в Finder»).
- `FullDiskAccess` (этап 1) — проверка: попытка открыть на чтение `~/Library/Application Support/com.apple.TCC/TCC.db`
  (без полного доступа macOS отвечает «Operation not permitted»; содержимое не читается).
- `SystemSettingsLinks` (этап 1, пополняется) — адреса панелей `x-apple.systempreferences:` в одном месте.
- `Trash` (этап 2) — перенос в Корзину через `NSFileManager trashItemAtURL` (вызов Objective-C из C#), в Finder работает
  «Вернуть». Если не хватает прав (папка принадлежит системе) — перенос через Finder (AppleScript, путь передаётся как
  аргумент), пароль тогда спрашивает сама macOS.
- `SafeDelete` (этап 2) — удаление кэшей через `openat/unlinkat/fstatat` с `O_NOFOLLOW`: путь открывается по одной папке
  от корня категории, символические ссылки не проходятся, подмена папки на ссылку после обхода ничего не удаляет; корень
  категории не удаляется.
- `AdminPrompt` (этап 3) — действия с правами администратора только через окно пароля macOS:
  `osascript -e 'on run argv' … 'do shell script … with administrator privileges with prompt …'`. Текст скрипта
  постоянный; команда, аргументы и текст подсказки приходят через `argv` и экранируются `quoted form of`. Одно действие
  пользователя — одно окно пароля (действие может состоять из нескольких команд, все перечислены в нашем
  подтверждении). Отмена в окне пароля → «Отменено — ничего не изменено».
- `CodeSignature` (этап 3) — `codesign -dv --verbose=2` (кто подписал), `codesign --verify --strict` (цела ли подпись),
  `spctl --assess --type execute -vv` для `.app` (решение Gatekeeper, нотаризация); кэш по пути и времени изменения.
- `Backups` (этап 3) — копии plist и прежних значений (прокси, DNS, hosts, объекты входа — JSON) в `Backups/<дата>/` до
  любого изменения; без копии изменение отменяется. Каталог копий с восстановлением — в «Настройках».

## Разделы

Анализ каждого раздела для «Главной» (`AnalyzeAsync`) только читает систему и никогда не вызывает запросов разрешений
macOS (объекты входа, Finder, папки «Документы»/«Рабочий стол»), — такие проверки идут только со страницы раздела по
кнопке. Пороги и важность находок — те, что указаны ниже; если настоящие данные покажут, что порог не подходит, он
меняется здесь же, в спецификации.

### Главная

- Оценка 0–100 и вердикт по `HealthScoring`, проверка всех разделов параллельно через `SmartScanner` (60 с на раздел),
  группы по важности, сравнение с прошлой проверкой («Было 52 → стало 78»).
- «Исправить найденное» — только находки с `AutoFixSafe` (обратимые, без пароля администратора) после одного
  подтверждения со списком. Остальные — «Открыть раздел» или своя кнопка исправления.
- Сведения о Mac: модель и чип, память (`system_profiler SPHardwareDataType -json`, без серийного номера), macOS
  (`sw_vers`), свободное место (`df -k -P`), время работы (`sysctl -n kern.boottime`).
- На этапе 1 «Главная» проверяет свободное место на диске; остальные проверки подключаются со своими разделами.
- HTML-отчёт (самодостаточная страница в стиле Windows-отчёта) и текст для буфера обмена — на этапе 5, когда есть все
  разделы.

### Очистка и диски

Категории (только данные пользователя, без прав администратора):

| Категория | Что | Правила |
|---|---|---|
| Кэши программ | `~/Library/Caches/*` | кроме `com.apple.*`, кэшей запущенных программ (по bundle id и имени), категорий ниже; файлы, изменённые за последний час, пропускаются |
| Журналы и сбои | `~/Library/Logs`, `~/Library/Logs/DiagnosticReports` | старше 7 дней, кроме журналов этой программы |
| Кэши браузеров | Safari, Chrome, Edge, Brave, Opera, Яндекс, Firefox | только папки кэша из белого списка (`Cache`, `Code Cache`, `GPUCache`, `cache2`, `ShaderCache`, `GrShaderCache`) в известных корнях браузеров; пароли, история, cookies, закладки, сессии, Local Storage — никогда; запущенный браузер пропускается («закройте Chrome») |
| Разработка | Xcode DerivedData, `CoreSimulator/Caches`, Homebrew (`brew cleanup`), npm (`~/.npm/_cacache`), pip, Yarn, CocoaPods | Xcode/симулятор не должны работать; архивы Xcode и iOS DeviceSupport только показываются с размером |
| Корзина | `~/.Trash` | размер; «Очистить корзину» через Finder с отдельным подтверждением — единственное безвозвратное удаление |

- Safari, контейнеры приложений и Корзина читаются только с полным доступом к диску; без него категория показывает
  «Нужен полный доступ к диску» и кнопку с инструкцией.
- Кэши и журналы удаляются через `SafeDelete`, занятые/недоступные файлы пропускаются и считаются в итоге.
- Диски: тома (`df -k -P`, `diskutil info -plist`): объём, свободно, место, которое macOS может освободить сама
  (purgeable); локальные снимки Time Machine (`tmutil listlocalsnapshots /`) — показываются с объяснением.
- Анализ места: самые большие папки в домашней папке (без перехода по ссылкам), большие файлы (порог 100 МБ / 500 МБ /
  1 ГБ, по умолчанию 500 МБ) и старые загрузки (старше 90 дней) — «Показать в Finder», «В Корзину». Перед обходом
  «Рабочего стола», «Документов», «Загрузок» программа предупреждает, что macOS может спросить доступ.
- Находки: кэши ≥ 500 МБ — средняя (`AutoFixSafe`), ≥ 100 МБ — низкая; Корзина ≥ 1 ГБ — низкая; свободно < 10 % или
  < 10 ГБ — важная, < 20 % — средняя; кэши разработки ≥ 2 ГБ — низкая.

### Процессы и автозагрузка

Процессы:

- Список из `ps -axww -o pid=,ppid=,uid=,pcpu=,rss=,etime=,comm=` и отдельно `… args=` (путь с пробелами не смешивается
  с аргументами), объединение по PID; имя, путь, пользователь, ЦП, память, время работы.
- Подпись: Apple, App Store, Developer ID (имя и Team ID), ad-hoc, без подписи, подпись повреждена.
- Эвристика (только подсказка, с причинами): нет подписи или ad-hoc вне папки программ; запуск из `/tmp`, `/private/tmp`,
  `/Users/Shared`, скрытой папки, `~/Library/Application Support` без `.app`; файл программы удалён; известное
  рекламное ПО (список для Mac).
- Действия: «Завершить» (только процессы текущего пользователя: SIGTERM, через 5 с — предложение завершить
  принудительно), «Показать в Finder», «Найти в интернете», «VirusTotal» (открывается страница по SHA-256, файл никуда
  не отправляется). Нельзя завершить: PID 0/1, `kernel_task`, `launchd`, `WindowServer`, `loginwindow`, саму программу,
  процессы других пользователей.

Автозагрузка:

- Источники: `~/Library/LaunchAgents`, `/Library/LaunchAgents`, `/Library/LaunchDaemons`; `/System/Library/Launch*`
  (Apple, скрыты по умолчанию, только чтение); службы из `launchctl print gui/<uid>` и `launchctl list` (в том числе
  зарегистрированные программами через SMAppService); отключённые — `launchctl print-disabled gui/<uid>` и `system`;
  объекты входа — через System Events (macOS один раз спросит разрешение; только по кнопке на странице).
- Для записи: метка, программа и аргументы, подпись программы, запущена ли (PID), последний код завершения, отключена ли,
  «сломана» (нет файла программы, plist не читается, нет метки).
- «Отключить/Включить» — обратимо: `launchctl disable|enable gui/<uid>/<метка>` + `bootout|bootstrap` (агенты из
  `~/Library` и `/Library/LaunchAgents` — без пароля); демоны из `/Library/LaunchDaemons` — `system/<метка>` через окно
  пароля. Перед изменением plist копируется в `Backups`.
- «Удалить» — только записи из `~/Library/LaunchAgents`: выгрузить, копия, plist в Корзину. Системные записи только
  отключаются.
- Объекты входа: удалить из списка (имя, путь и «скрывать» сохраняются в `Backups`, можно вернуть). «Разрешить в фоне»
  для программ на SMAppService — кнопка открывает «Объекты входа» в Системных настройках.
- Находки: сломанная пользовательская запись — средняя (`AutoFixSafe`: отключить); неподписанная или ad-hoc запись,
  программа которой лежит в папке, доступной пользователю на запись, — важная; известное рекламное ПО — важная;
  больше 15 сторонних записей — совет.

### Программы

- Где: `/Applications/*.app`, `/Applications/*/*.app` (папки вроде «Утилиты» и папки производителей), `~/Applications`;
  встроенные программы Apple (`/System/Applications`) показаны отдельно и не удаляются.
- Сведения: название, bundle id, версия (Info.plist), разработчик и подпись, источник (App Store — есть
  `Contents/_MASReceipt`), архитектура — Apple Silicon / Universal / только Intel (Rosetta) по заголовку Mach-O основного
  файла (чистый код), размер (считается в фоне, без перехода по ссылкам), последний запуск
  (`mdls -raw -name kMDItemLastUsedDate`).
- Удаление:
  1. подтверждение со списком того, что будет удалено;
  2. если программа запущена — просим закрыть её («Закройте X и нажмите «Продолжить»»), принудительное завершение —
     отдельная кнопка с предупреждением о несохранённых данных;
  3. если у программы есть свой деинсталлятор (`Uninstall*.app` внутри или рядом) — сначала предлагаем его;
  4. программа — в Корзину (`Trash`; если она принадлежит системе — через Finder, пароль спросит macOS);
  5. остатки в `~/Library` с галочками → в Корзину.
- Остатки ищутся только по точному bundle id: `Application Support/<id>`, `Caches/<id>`, `Preferences/<id>.plist`,
  `Preferences/ByHost/<id>.*.plist`, `Saved Application State/<id>.savedState`, `Containers/<id>` (нужен полный
  доступ), `HTTPStorages/<id>`, `WebKit/<id>`, `Cookies/<id>.binarycookies`, `LaunchAgents/<id>*.plist`. По точному
  имени программы — `Application Support/<имя>`, `Logs/<имя>` (отмечены, только если нет другой программы с тем же
  именем). `Group Containers/<Team ID>.*` — показываются без галочки (их часто делят программы одного разработчика).
- Нежелательные программы — свой список для Mac (MacKeeper, Advanced Mac Cleaner, Mac Auto Fixer, Smart Mac Booster,
  Mac Cleanup Pro, MacBooster, Genieo, Search Baron / Search Marquis, VSearch и др.) с причиной, «потенциально
  нежелательная», не «вирус».
- Находки: нежелательная программа — важная; не запускалась больше 180 дней и занимает ≥ 500 МБ — совет; только для
  Intel — совет.

### Безопасность и сеть

| Проверка | Как читаем | Находка | Исправление |
|---|---|---|---|
| SIP | `csrutil status` | выключена — критично | только инструкция (режим восстановления) |
| Gatekeeper | `spctl --status` | выключен — важная | включить через окно пароля |
| FileVault | `fdesetup status` | выключен — важная | кнопка «Открыть настройки FileVault» (нужно сохранить ключ восстановления) |
| Брандмауэр | `socketfilterfw --getglobalstate`, `--getstealthmode` | выключен — средняя; невидимость — совет | включить через окно пароля |
| Обновления macOS | `softwareupdate -l` (в фоне, до 60 с), `/Library/Preferences/com.apple.SoftwareUpdate.plist` | есть обновления — средняя, обновления безопасности — важная; автопроверка или установка ответов безопасности выключены — важная | кнопка «Обновление ПО» |
| Версия macOS | `sw_vers` + таблица поддерживаемых версий в коде | не одна из трёх последних — важная | инструкция |
| XProtect | версия и дата `XProtect.bundle` | старше 60 дней — низкая | кнопка «Обновление ПО» |
| Вход без пароля, гость | `/Library/Preferences/com.apple.loginwindow.plist` | автовход — важная; гость — низкая | инструкция и кнопка «Пользователи и группы» |
| Удалённый доступ | `launchctl print-disabled system` (SSH, общий экран) | включён — средняя | кнопка «Общий доступ» |
| Профили конфигурации | `system_profiler SPConfigurationProfileDataType -json` | профиль меняет браузер (домашняя страница, поиск), прокси, ставит корневой сертификат — важная; MDM — «управляется организацией», совет | кнопка «Профили» (удаляет сам пользователь) |
| Прокси | `scutil --proxy` | неожиданный HTTP/HTTPS/SOCKS прокси или PAC — важная | выключить: копия значений, `networksetup` через окно пароля |
| DNS | `scutil --dns`, `networksetup -getdnsservers` | неизвестный DNS (не роутер и не известный публичный) — средняя | вернуть автоматический DNS: копия, окно пароля |
| hosts | `/etc/hosts` + `HostsRules` (копия из Windows-версии) | перехват сайтов или блокировка обновлений/защиты — важная | закомментировать строки: копия, окно пароля |
| Wi-Fi | `system_profiler SPAirPortDataType -json` | открытая сеть — средняя, WEP — важная | совет; имя сети не сохраняется ни в журнале, ни в отчёте |

Исправления с паролем администратора не входят в «Исправить найденное» — у каждого своя кнопка.

### Настройки

О программе (версия, ссылка на репозиторий); полный доступ к диску (состояние, инструкция, кнопка); журнал (просмотр,
«Открыть папку»); папка данных программы. С этапа 3 — резервные копии (список, «Показать в Finder», «Восстановить» —
plist на место + `launchctl enable/bootstrap`, прежние прокси/DNS/hosts через окно пароля, объекты входа — снова
добавить; каждый этап добавляет восстановление своих копий). С этапа 6 — обновления (версия, дата проверки, «Проверить
сейчас», «Обновляться автоматически», по умолчанию включено).

## Правила безопасности

1. Ничего не меняется без подтверждения со списком того, что будет сделано; в тестах и режиме скриншотов — всегда «Нет».
2. Проверки только читают; изменения — только по кнопке.
3. Перед изменением — резервная копия; без копии изменение отменяется.
4. Сразу удаляются только кэши и журналы; всё остальное — в Корзину; безвозвратно — только «Очистить корзину».
5. Нет перехода по символическим ссылкам и выхода за корень категории; не трогаются `/System`, `/usr` (кроме
   `/usr/local`), пути под SIP, пароли, история, cookies, связка ключей; корни категорий и домашняя папка не удаляются.
6. Права администратора — только через окно пароля macOS, по одному действию; программа не работает от root и не
   хранит пароль; команды передаются как данные, текст из файлов и настроек никогда не вставляется в скрипт.
7. Автозагрузка отключается обратимо; системные записи только отключаются.
8. Эвристика только подсказывает; «подозрительное» не удаляется автоматически.
9. Полный доступ к диску не обязателен: программа объясняет, что без него не проверяется, и ведёт в нужную панель.
   Разрешения macOS (Finder, System Events, папки) запрашиваются только тогда, когда нужны.
10. Системные и чужие процессы завершить нельзя.
11. Каждое изменение — в журнал (`Log.Action`); ошибки для пользователя — по-русски (`ErrorText`).

## Тестирование

Настоящая система не меняется ни в одном тесте.

1. **Везде (ПК разработки на Windows и CI):**
   - разбор вывода утилит по образцам `Fixtures/<утилита>/<случай>.*` — `launchctl print/list/print-disabled`,
     `codesign -dv`, `spctl`, `csrutil`, `fdesetup`, `socketfilterfw`, `system_profiler -json`, `ps`, `df`,
     `diskutil -plist`, `tmutil`, `softwareupdate -l`, `scutil --proxy/--dns`, `networksetup`, `sw_vers`, plist XML и
     двоичные; на каждую утилиту — «всё хорошо», «проблема», «пустой или странный вывод», «ошибка/нет прав»;
   - правила: эвристика, автозагрузка, остатки программ, белый список кэшей браузеров, защита путей, нежелательные
     программы, находки для «Главной», заголовки Mach-O;
   - сервисы с `FakeCommandRunner` и временной папкой вместо домашней: копия создаётся до изменения, при «Нет»
     ничего не меняется, в Корзину/удаление уходят только нужные файлы;
   - обновления: поддельный HTTP, тестовая пара ключей, подменённые и испорченные файлы и архивы (zip slip, ссылки,
     лишний размер);
   - интерфейс через Avalonia.Headless: страницы открываются, привязки работают, ошибок в журнале нет; при заданной
     переменной `MAC_SCREENSHOTS_DIR` тесты сохраняют снимки страниц на данных из образцов (так их можно снять и на
     Windows).
2. **Только macOS (машины CI `macos-14` и `macos-latest`, Apple Silicon):** все тесты из п. 1 плюс тесты с атрибутом
   «только macOS»: настоящие утилиты только на чтение (`sw_vers`, `ps`, `df`, `csrutil status`, `codesign` на `/bin/ls`
   …) — живой вывод сверяется с парсерами; `SafeDelete`, `Trash`, распаковка обновления — на файлах во временной папке
   (в том числе подмена папки на символическую ссылку).
3. **Образцы:** `tools/mac/capture-fixtures.sh` на машине CI сохраняет вывод утилит в артефакт; скрипт сам заменяет имя
   пользователя, имя компьютера, серийный номер, UUID оборудования и MAC-адреса на заглушки, перед коммитом образцы ещё
   раз просматриваются.
4. **Скриншоты настоящей системы:** `--screenshots <папка> [--page Dashboard,Settings] [--no-scan] [--size 1040x660]` —
   данные программы во временной папке, все диалоги «Нет», для каждой страницы — только чтение, `NN-Key.png` и
   `log.txt`, код выхода 1 при ошибках в журнале. В CI — на машине macOS, артефактом.
5. **Пользователь** после каждого этапа скачивает `.app` из артефакта CI и проверяет на своём Mac то, что CI не может:
   окна пароля, разрешения macOS, Корзину и «Вернуть».

## Упаковка и подпись

- `dotnet publish src/PcCleaner.Mac -c Release -r osx-arm64 --self-contained -p:PublishSingleFile=true` (.NET внутри
  программы). Одним файлом — потому что `codesign` считает кодом каждый файл в `Contents/MacOS` и не подписывает
  сборки .NET (`.dll`) там; в single-file они внутри исполняемого файла, рядом остаются только `.dylib` Avalonia,
  Skia и HarfBuzz (Mach-O). `make-app.sh` проверяет, что в папке публикации только Mach-O.
- `tools/mac/make-app.sh` собирает `WaterCa7s PC Cleaner.app`: исполняемый файл `Contents/MacOS/WaterCa7sPcCleaner`,
  Info.plist — `CFBundleIdentifier` `io.github.waterca7.pccleaner`, версия, `LSMinimumSystemVersion` 14.0,
  `CFBundleDevelopmentRegion` ru, `LSApplicationCategoryType` utilities, `NSAppleEventsUsageDescription` (по-русски:
  зачем нужны Finder и System Events), `CFBundleIconFile` AppIcon.
- Иконка `AppIcon.icns` — «кошачья капля» в сетке значков macOS (скруглённый квадрат с полями), все размеры 16–1024;
  рисует `tools/mac/make-icon.ps1` (Windows PowerShell 5.1, тот же рисунок, что `tools/make-icon.ps1` Windows-версии),
  файл хранится в репозитории.
- Подпись (`tools/mac/sign.sh`): каждый Mach-O внутри `Contents/MacOS`, затем сам bundle — сертификатом из секретов
  (импорт во временную связку ключей) или ad-hoc без них. Без hardened runtime (нотаризации нет, особые разрешения .NET
  не нужны). Проверки: `codesign --verify --deep --strict`; требование подписи (`codesign -d -r-`) — в журнал CI.
- Сертификат: RSA 2048, `extendedKeyUsage=codeSigning`, CN «WaterCa7s PC Cleaner Signing», 10 лет; создаётся на ПК
  разработки через `openssl`, `.p12` в формате, который понимает `security import`. Резервная копия —
  `%USERPROFILE%\WaterCa7sPcCleaner-signing\mac\`; в секреты — `gh secret set` после согласия пользователя. Потеря
  сертификата = после следующего обновления macOS один раз заново спросит разрешения.
- Архив `WaterCa7sPcCleaner-osx-arm64.zip` (`ditto -c -k --keepParent`).
- README (по-русски): распаковать, перетащить в «Программы» (иначе macOS запускает программу из временной папки только
  для чтения и автообновление не работает — программа это замечает и просит переместить её), первый запуск —
  Системные настройки → Конфиденциальность и безопасность → «Всё равно открыть».

## CI

- `ci.yml` (каждый push и PR): матрица `macos-14` и `macos-latest` — `setup-dotnet` 10.0.x, сборка
  `WaterCa7sPcCleaner.Mac.sln`, все тесты (со снимками на образцах), скриншоты настоящей системы, образцы утилит; на
  `macos-latest` ещё `.app`, подпись, zip. Артефакты: `WaterCa7sPcCleaner-osx-arm64` (zip), `mac-screenshots-<os>`,
  `mac-fixtures-<os>`.
- `release.yml` (тег `v*`, только после согласия пользователя на релиз): `macos-latest` — версия тега совпадает с
  `<Version>` проекта, есть `docs/release-notes/<версия>.md`; сборка, тесты, `.app`, zip;
  `tools/mac/make-update-manifest.sh` пишет `update.json` и подписывает его (`openssl dgst -sha256 -sign`, ключ из секрета
  `UPDATE_SIGNING_KEY`); тест программы проверяет подписанный `update.json` встроенным ключом; `gh release create` с zip,
  `update.json`, `update.json.sig`.

## Автообновление

Та же схема, что у Windows 1.1.0 (спецификация `docs/superpowers/specs/2026-10-17-auto-update-design.md`
Windows-репозитория), но со своим репозиторием и своим ключом:

- Ключ подписи — **своя пара ECDSA P-256** для Mac: открытый в `tools/update-signing-public.pem` и
  `Core/Updates/UpdateKeys.cs` (тест сверяет), закрытый — в секрете `UPDATE_SIGNING_KEY` Mac-репозитория и в резервной
  копии `%USERPROFILE%\WaterCa7sPcCleaner-signing\mac\`. Отдельный ключ: утечка одного не затрагивает другую программу.
- `update.json` в каждом релизе Mac-репозитория:

```json
{
  "version": "1.0.0",
  "published": "2026-11-01T12:00:00Z",
  "notes": "Что нового — текст на русском",
  "files": {
    "osx-arm64": {
      "name": "WaterCa7sPcCleaner-osx-arm64.zip",
      "url": "https://github.com/WaterCa7/WaterCa7-s-pc-cleaner-mac/releases/download/v1.0.0/WaterCa7sPcCleaner-osx-arm64.zip",
      "size": 41234567,
      "sha256": "…"
    }
  }
}
```

1. **Проверка** при запуске в фоне (не в режиме скриншотов, не в сборке для разработки, если включено «Обновляться
   автоматически»): `update.json` и `.sig` с `releases/latest/download/` Mac-репозитория, подпись, запись `osx-arm64`:
   имя — простое имя файла `.zip`, ссылка — на релиз именно этой версии этого репозитория, размер 1–500 МБ, SHA-256 —
   64 hex. Нет сети, ошибка, подпись не сходится, версия не новее → только запись в журнал.
2. **Скачивание** в `~/Library/Application Support/WaterCa7sPcCleaner/Updates/<версия>/…zip.partial`, сверка размера и
   SHA-256, переименование, рядом `update.json` и `.sig`. Полоса: «Обновление до X готово — установится при следующем
   запуске · Перезапустить сейчас».
3. **Установка** при следующем запуске, до окна (или по кнопке):
   1. подпись `update.json` и версия проверяются заново;
   2. zip открывается с запретом записи, SHA-256 считается по тем же байтам, из которых он распаковывается (свой
      распаковщик) в `<программа>.app.new` рядом с текущей: все записи — внутри `WaterCa7s PC Cleaner.app/`, без `..`,
      абсолютных путей и символических ссылок; права файлов (исполняемость) берутся из архива;
   3. проверка распакованной программы: `codesign --verify --deep --strict`; bundle id и версия в Info.plist; если
      текущая программа подписана сертификатом — новая должна удовлетворять тому же требованию подписи
      (`codesign --verify -R="=<требование текущей>"`);
   4. текущая программа переименовывается в `.app.old`, `.app.new` — на её место; запуск
      `open -n <программа> --args --updated-from <старая версия>`, текущий процесс завершается;
   5. новая версия удаляет `.app.old` и папку `Updates/<версия>`, полоса «Программа обновлена до X · Что нового».
4. **Ошибки:** любой сбой на шагах 2–4 — прежняя программа возвращается на место, `.new` удаляется, запись в журнал;
   счётчик неудач в `Updates/state.json`, после 2 неудач версия не ставится автоматически — «Скачать вручную».
   Папка программы недоступна для записи, программа запущена из временной папки macOS (`/AppTranslocation/`), с образа
   диска или не из `.app` → не ставим: «Переместите программу в «Программы»» или «Скачать вручную».
5. Файл, скачанный самой программой, не получает отметку карантина — повторное «Всё равно открыть» не нужно; с тем же
   сертификатом сохраняется и полный доступ к диску.
6. Сборка для разработки (программа запущена не из `….app/Contents/MacOS/`) не проверяет и не ставит обновления.

## Этапы

Каждый этап работает сам по себе, покрыт тестами, проходит CI и проверяется пользователем на Mac. План каждого этапа
пишется в `docs/superpowers/plans/`, когда закончен предыдущий (нужны настоящие образцы вывода утилит из CI).

1. **Фундамент:** проекты и решение, тема, оболочка, сервисы Core этапа 1, «Главная» (сведения о Mac, проверка места на
   диске, оценка), «Настройки», режим скриншотов, CI, `.app`, иконка, сертификат.
2. **Очистка и диски.**
3. **Процессы и автозагрузка.**
4. **Программы.**
5. **Безопасность и сеть**, HTML-отчёт «Главной».
6. **Автообновление.** Затем, после согласия пользователя, — `release.yml` и релиз 1.0.0.
